# Direct analytics runner (048A)

The deleted Vercel project no longer schedules analytics. The review candidate runs the existing report, digest and delivery code inside the GitHub-hosted Node runner; it does not call the long-running Timeweb HTTP routes. Schedules remain Monday 06:30 UTC and daily retry 08:15 UTC. No workflow runs until separately merged and activated. The `analytics-production` GitHub environment must be protected by the owner before secrets are configured; no pull-request or non-main ref is permitted. GitHub schedules can be delayed or dropped and the concurrency group is not a durable queue.

The workflow uses Node 24, `npm ci --include=dev` and Vite's server-side module loader in middleware mode without a listening HTTP server. The `server-only` marker resolves to Next's server-side empty marker only within this server process. Existing TypeScript reporting, privacy projection, idempotency, PostgreSQL client and Resend delivery remain authoritative. The job has a 20 minute upper limit; a killed process may leave an ambiguous provider outcome and does not prove email was not delivered.

## Owner activation gate — no credentials are configured by this change

1. Verify the deleted Vercel scheduler is absent and the Timeweb delivery flag remains false; do not run an HTTP scheduler concurrently.
2. Protect the `analytics-production` GitHub environment, restrict branches to `main`, and set environment secrets `ANALYTICS_DATABASE_URL`, `RESEND_API_KEY`, `ANALYTICS_DELIVERY_SENDER`, `ANALYTICS_DELIVERY_RECIPIENT`, `YANDEX_METRIKA_OAUTH_TOKEN`. Set environment variable `YANDEX_METRIKA_ID` to the correct counter ID. Set `ANALYTICS_DELIVERY_ENABLED=true` only after separate approval; an absent or false value fails closed. No `CRON_SECRET` is required by this runner.
3. For IPv4 runners, select the project's Supabase **shared Session pooler** connection string and port 5432 from the dashboard; do not guess the hostname. Keep TLS enabled and use a dedicated least-privilege role with only the existing reporting reads and delivery-ledger access. Verify networking, permissions, rate limits and read/write behavior in an isolated environment first. Never print the URI or credentials. See https://supabase.com/docs/guides/database/connecting-to-postgres.
4. Reconcile `weekly:2026-W43` and `weekly:2026-W44` against ledger and provider before authorizing any real delivery. W44 is intentionally not generated by this runner. Historical W44 recovery requires its own separately reviewed and authorized path.

## Missing weeks, retries and reconciliation

Weekly runs are valid only during Moscow Monday 00:15–23:44, use a single frozen clock, and check the immediately completed ISO week before delivery. The runner checks ledger coverage from the owner-confirmed W43 baseline to the prior week; a missing or non-sent week fails closed rather than silently passing over it. W43 and other rows are not removed by this runner's retry sweep. Other existing code or maintenance jobs may still apply retention, so preserve W43 evidence independently.

The operator may select `weekly` or `retry` via manual dispatch after separate authorization. Do not use weekly dispatch as a backfill. A missing W44 blocks later weekly delivery until reconciled; no current report is silently substituted. The retry sweep excludes W44 even if it appears as due, and fails visibly for owner action. If a job or provider outcome is uncertain, inspect the ledger and Resend before any action. A failed/expired `sending` claim, transport error, 5xx or concurrent provider response is `provider_reconciliation_required` and is never automatically resent. Definitive retryable failures such as provider rate limiting remain bounded by the existing ledger attempt policy. Failure-notification emails are disabled for this runner to avoid untracked ambiguous sends; use Actions and sanitized logs for alerts.

The intended Session pooler path, real GitHub environment protection, production secrets, live schedule, historical source completeness, and actual Resend delivery are not verified by local tests. Do not activate until all are checked and the owner separately authorizes activation and W44 recovery.
